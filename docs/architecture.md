# Research extraction architecture

This package is a research extraction assembled from six selected JavaScript modules: `edge-schema`, `assertion-v2`, `verification-identity`, `delivery-decision`, `finding-grounding`, and `governed-receipt-core`. Its package name is `fga-research-extract`. Four modules retain their source bytes; `edge-schema` and `assertion-v2` receive bounded local corrections described in [negative results](negative-results.md). The edge and grounding functions are included as internal diagnostic material; their presence does not make this package compatible with an earlier public API. The exact source revision, per-file hashes, changes, and package bytes are recorded separately in the provenance material.

The modules cover separate decisions. `edge-schema` labels graph relations and can demote a heuristic finding's `FAIL` verdict to `REVIEW`. The local correction keeps known model-proposed relations ineligible even if a caller supplies a stronger `status`. `assertion-v2` compares a supplied transition with a supplied contract after structural, source, approval, environment, navigation, and evidence checks. Its local correction requires predicate-specific observation data before comparison. `verification-identity` describes the comparison identity. `finding-grounding` checks the internal shape and hashes of a supplied grounding record. `delivery-decision` computes a six-gate decision from supplied assertions, certification receipts, a dispute decision, and a blocking policy decision. `governed-receipt-core` provides the record and hash utilities used by grounding.

These functions accept caller-provided objects. This extraction contains no browser capture, authoritative contract resolver, external receipt store, issuer, runtime adapter, or change gate. A field such as `status: "OBSERVED"`, `approval.status: "APPROVED"`, or `issuerAdmissionStatus: "ADMITTED"` is input data here; the package does not establish who produced it. Hash agreement establishes consistency among supplied bytes, not independent authority over the underlying event or contract.

There are two different uses of `BLOCK` to keep apart. The raw `deriveDeliveryDecision` function returns the enum `BLOCK` when all six gates evaluate as satisfied. Synthetic, self-declared receipts can satisfy those gates. Its result still says `activationStatus: "NOT_ACTIVATED"`, `finalVerifierEligible: false`, and `canClaimVerifiedFixed: false`. This package does not wire that enum to CI, merge control, customer delivery, or any other action. `classifyFindingGrounding` likewise returns `hardEligible: false` even for an internally consistent candidate record, because it performs no independent authority readback.

The selected files deliberately omit the original CI policy, proof packet builders and verifiers, readiness logic, browser runner, packs, and final fixed-claim issuer. The source CI policy was consulted to understand the boundary, but copying it without its broader caller and authority context would suggest a gate this candidate cannot operate. The package entry point and export list must be reviewed as a new research API; no compatibility with the original `public/v1` surface is claimed.

The examples in `test/research.test.mjs` use synthetic records. They check local behavior and failure modes, not observed product behavior. See [claims and limits](claims-and-limits.md) for each claim and [negative results](negative-results.md) for unresolved paths.
